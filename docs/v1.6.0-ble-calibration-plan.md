## 校准交互契约

1. 开始前说明三个姿势的目的：张开作为伸展端点，握拳作为弯曲端点，最后四指保持张开、拇指靠向食指作为拇指摆动端点。每次只展示一只目标手，摄像头/手别变化使本次采集作废。
2. 每步由用户点击一次“开始采集”启动，清除之前的帧；App 自动采集五个新的、间隔采样的稳定结果，跨度至少约 600ms。不是录视频，不用连续点击五次，也不能在点击之前就靠后台帧凑满计数。
3. 采集中显示 0/5→5/5；稳定性不足时明确重计，失手/换手/切摄像头时中断并要求再次点击。不得静默使用旧帧。
4. 张开/握拳范围应在第二步检查，失败后留在可操作的步骤，并提供重采入口。第三步检查其它四指保持张开及拇指变化范围。
5. 标定 schema 升为 7，旧版后台滚动采样的 schema-6 标定不能自动沿用，升级后必须重新校准；用户调参设置保留。未校准、采集中、错误手别、多手、过期帧均不能产生手势控制。MediaPipe 原始 normalized/world landmarks、category/confidence 继续独立保留，预览变换不修改原始数据，retargeting 仍为单独层。
6. 小屏幕/大字体下按钮必须可见可达，不因过长说明遮住操作；单位测试只是 UI 约束证据，最终仍需手机实测。

## BLE GATT 契约

ESP32-S3 是 BLE Peripheral，Android 是 Central。保留 USB CDC 与 Wi-Fi AP/STA WebSocket，不让电脑改换网络。

| 角色 | UUID | 内容 |
|---|---|---|
| 服务 | `8c6f4a20-6c0b-4b7a-9d27-6df8a3210001` | Android 按服务 UUID 扫描，用户明确选择设备 |
| 命令 | `8c6f4a20-6c0b-4b7a-9d27-6df8a3210002` | 加密、已绑定连接上的 Write with response；恰好 16 字节 |
| 响应 | `8c6f4a20-6c0b-4b7a-9d27-6df8a3210003` | Notify；16 字节 USB 兼容回包 |
| 身份 | `8c6f4a20-6c0b-4b7a-9d27-6df8a3210004` | Read；JSON 固件类型/版本、手别、协议及能力 |

初始支持 `CTRL_POS=0x11`、`GET_POS=0x22`、`HOMING=0x01`。其余扭矩、改 ID、修整、配网命令不通过 BLE 暴露。沿用现有 USB 编解码；默认 ATT payload 足以承载 16 字节，不引入 JSON 分片。

- Android 连接过程：权限→扫描→用户选设备→连接/绑定→发现服务→读取并校验身份→启用通知；完成前不得显示可控制。
- GATT 操作串行化、有界等待；控制目标只保留最新待写值，切换模式/断连清除待写值和旧代际回调。
- 固件回调只做鉴权、长度/操作码校验与入队，执行器调用由主循环完成；位置命令合并，队列有界、有时效，断连丢弃该代际待处理命令。
- 加入独立 BLE 控制来源和仲裁，不能凭只读查询续占控制权。断连清队列不等于机械急停，不承诺自动归零/掉扭矩。
- GATT write 成功只表示传输写入确认，不表示执行器达到目标。状态需读取真实回包。

### 安全限制

要求加密与绑定，但无输入/显示设备使用 Just Works，**不提供 MITM 身份认证**。自定义 UUID、广播名称和可读身份 JSON 也不是认证。应在受控近距离环境配对；第一次配对与真实机械手连接仍需用户监督。不能宣传为工业安全控制或急停通道。

## 归位安全与 BLE 生命周期补充（待本次云端验证）

- BLE 归位等待 `gBusMux` 后重验连接代际、连接 handle 和到达时限；验证在 baseline reset / 电机操作前执行。失效时释放总线并恢复 busy，不取消目标、不写 NVS、不重置角度缓存、不发送成功 ACK、不续占控制权。USB/Wi-Fi/启动保留原归位入口。
- 新增云端 native harness：在获取总线期间模拟断连、恰好到期以及有效指令，检查副作用和单次加锁/解锁。
- 新增三项 Android BLE service 回归测试：未连接发送不触碰 GATT；断连清理活动/排队写入并拒绝旧代际回调；操作超时关闭会话且迟到回调不能恢复连接。它们不包含真实手机配对或身份错误服务的集成验收。
- 上述补丁未在本地构建或运行测试，必须以本次提交的 GitHub Actions 结果为准。
